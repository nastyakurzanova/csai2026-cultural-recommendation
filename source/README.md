# Этап 6 Подготовка Flickr и Wikidata

Тема: «Адаптивная рекомендация объектов культурного наследия на основе графа знаний и динамики пользовательских предпочтений».

Дата подготовки: 26 октября 2026 года. Это проверка и подготовка источников. Обучение моделей, разделение train/validation/test и проверка гипотез не выполнялись.

## Основные результаты

- Исходный архив содержит 153 208 строк фотографий, 236 записей мест, восемь городов.
- 53 строки с непригодными для выбранного поведенческого сценария временными метками отделены; 153 155 строк сохранены в производных фотографиях.
- Восстановлено 33 778 посещений. Это серии подряд идущих фотографий одного места в исходной последовательности; возвращения после другого места сохраняются.
- Два точных дубликата каталога объединены: Osaka Castle 8/13, Belvedere 7/12. В каждой паре фотографии имеют только один из исходных ID. После объединения 234 места.
- Для всех исходных названий получены кандидаты Wikidata. Три из них являются страницами неоднозначности, Zepp требует определения конкретной площадки, пара названий музея в Эдинбурге требует предметной проверки.
- Сохранено 1 239 исходных утверждений Wikidata. Сведения актуальны на момент скачивания 2026 года, не являются историческим снимком состояния 2014 года.
- Приоритетные города: Будапешт и Вена. Эдинбург дополнительный. Итоговая культурная выборка требует проверки принадлежности каждого объекта.

## Файлы

### Исходные данные

- `raw/data-ijcai15.zip` — неизменённый архив со страницы автора.
- `raw/data-ijcai15/` — извлечённые оригинальные файлы и авторские README.
- `raw/flickr_manifest.json` — источник, время получения, размер и SHA-256.
- `raw/wikidata/*.json` — ответы API Wikidata, перенаправления Wikipedia, подписи сущностей и описание снимка. Сведения об источниках утверждений полностью доступны в сырых ответах.

### Основные подготовленные таблицы

- `processed/poi_catalog_prepared.csv` — канонический каталог с флагами проверки.
- `processed/poi_aliases.csv` — все исходные идентификаторы и их канонические значения.
- `processed/visits_prepared.csv` — посещения после объединения дубликатов, флаги пригодности последовательности и сопоставления сущности.
- `processed/sequence_audit.csv` — проверка времени и последовательностей. Ключ составной: city, userID, seqID.
- `processed/wikidata_alignment.csv` — сущность-кандидат, способ сопоставления, расстояние, редакция и статус каждой исходной записи.
- `processed/cultural_statements.csv` — исходные культурные утверждения по десяти свойствам. Утверждения по исходным дублям не удалены; при построении графа следует канонизировать POI и дедуплицировать statement_id.
- `processed/cultural_entity_labels.csv` — английские подписи связанных сущностей.
- `processed/data_readiness.csv` — сводные диагностические показатели по городам.
- `processed/quality_flags.csv`, `processed/shared_entity_review.csv`, `processed/quarantine_*.csv` — проблемы и записи для предметной проверки.

### Предварительные и промежуточные таблицы

- `processed/cultural_visits_provisional.csv` — предварительный отбор по исходной категории, согласованности сущности и времени. Не является окончательной культурной выборкой.
- `processed/history_feasibility_provisional.csv` — диагностическая доступность истории H2.
- `processed/photos_clean.csv`, `processed/visits_clean.csv`, `processed/poi_catalog_audited.csv`, `processed/city_audit.csv`, `processed/category_counts.csv` — промежуточные таблицы до канонизации. В имени clean подразумевается техническая обработка, а не завершённая предметная проверка. Для следующего этапа основными являются prepared-таблицы.
- `reports/Etap6_Podgotovka_dannyh.docx` — краткий отчёт.
- `reports/audit.json`, `reports/preparation_summary.json` — машиночитаемые результаты.

## Правила и ограничения

1. Исходные файлы не изменены. Отсутствующих сведений не добавляли предположениями.
2. Граница допустимой первичной метки: больше Unix epoch и не позже конца 2015 года, поскольку источник опубликован в 2015 году. Более ранние фотографии могут быть реальными историческими снимками, но не приняты в текущий поведенческий сценарий. Граница не доказывает достоверность всех оставшихся дат.
3. 423 оставшиеся фотографии до 2000 года сохранены; содержащие их последовательности исключены из диагностического отбора до проверки. Порог 2000 — явная предварительная настройка, не вывод об истинной дате посещения; его нужно пересмотреть и проверить чувствительность перед экспериментом.
4. При одинаковом времени разных POI фотографиям не приписывается достоверный порядок. В агрегированных таблицах порядок технически стабилизирован по photoID; такие последовательности помечены и целиком исключены из предварительной диагностики. 53 отделённые строки не пересекаются по userID/seqID с оставшимися последовательностями своих городов, поэтому их удаление не создаёт искусственных переходов внутри сохранившейся последовательности.
5. Согласованность координат в пределах 2 км — фильтр грубых ошибок, не подтверждение идентичности. В таблицах `scope_verified=False`: окончательная культурная принадлежность ещё не установлена.
6. Категории Historical, Cultural, Museum, Palace, Architectural, Religious, Religion, Building используются только для первоначального диагностического отбора. Культурные памятники и здания могут находиться и в других категориях. Их необходимо разметить индивидуально.
7. Три страницы неоднозначности, Zepp и пара Edinburgh 3/26 исключены из предварительной культурной диагностики, а не потеряны из исходного набора. Новые соответствия нужно фиксировать отдельными проверяемыми правками.
8. H2-диагностика: не менее 3 предварительных культурных посещений в более ранних последовательностях и не менее 3 в текущей; после префикса из 2 мест считаются доступные следующие позиции. Это не утверждённый протокол, не тестовый набор и не проверка изменения интересов. Временной разрыв между последовательностями ещё не доказывает наличие разных поездок или устойчивых долгосрочных предпочтений.
9. Снимок Wikidata 2026 года нельзя автоматически считать знанием, доступным во время посещений. До обучения нужно проверить временную применимость свойств, событий, статусов, переездов и идентичности зданий/организаций.
10. В сырых cultural_statements сохраняются все десять выбранных свойств, включая generic P31 и части P527. Их наличие не означает, что они полезны или допустимы в финальной модели. Сравнение с обычными культурными признаками необходимо, чтобы отделить пользу графовой структуры от добавления информации.
11. Исходный глобальный poiFreq исключён из производных фотографий. Все обучаемые статистики будут пересчитаны на обучающей истории.
12. Не смешивать единицы: строки фотографий, серии посещений, уникальные user–POI пары и исходные последовательности имеют разные количества. Дубликаты названий не удаляют историю пользователя.

## Воспроизведение

Проверенные версии Python-библиотек указаны в requirements.txt. Рабочий каталог определяется относительно расположения скриптов.

```bash
python -m pip install -r requirements.txt
python scripts/fetch_flickr.py
python scripts/prepare_data.py
python scripts/fetch_wikidata.py
python scripts/finalize_data.py
python scripts/build_report.py
```

Скрипты используют сохранённые сырые ответы при их наличии. Для повторного получения актуального Wikidata используйте отдельную копию проекта с пустой папкой raw/wikidata; такой запуск даст новый снимок и может изменить результаты. Скрипт останавливает конкретный сетевой запрос при HTTP 429, не обходит ограничения сервиса.

Для отчёта использован python-docx. Рендер DOCX проверен отдельно; страницы QA не включены в пакет. CSV предназначены для программного анализа, XSLX-книга не создавалась.
